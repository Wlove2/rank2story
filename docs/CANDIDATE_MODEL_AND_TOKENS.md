# 候选质量与 Token 消耗

Rank2Story 更适合在创作前期**提供有市场线索的故事方向和结构化灵感**：从题材切入，尝试不同的冲突、开篇与情节回报，再用编辑和原创性检查筛选候选。它并不是“一键生成可直接投稿的成熟小说”。

## 生成的候选还需要作者打磨

五张展示卡来自真实运行，并保留了当时的初步自动评审结果。这意味着卡片有明确的故事结构，**不意味着所有人物动机和因果都已经严密**。

例如 A-C02 的“身份反转”设定，主角长期忍受羞辱只为等一句悔恨，动机仍显单薄；商业反击为何持续加重旧伤、释怀后身体痛感为何消失，也缺少能说服读者的机制。它有可继续改写的冲突和情绪方向，但需要重新梳理代价设定、人物选择与结局，而不是照搬成稿。

模型的写作能力、长上下文理解和推理参数，都可能影响创意质量与审核判断。使用推理能力更强或更适合中文创作的模型，**有可能**改善逻辑连贯性与细节，不过并不保证每个故事都更好；重要情节仍应由作者复核。

## 一次真实候选运行的 Token 用量

以下来自 **2026-09-05** 的历史短篇候选运行：生成 9 个故事方向，经审核留下 5 张卡。这一批共保存了 **36 次模型响应**，每次均带有模型返回的 `usage` 信息，累加结果为：

| 指标 | 实际用量 |
| --- | ---: |
| 输入 Token | **332,861** |
| 输出 Token | **104,823** |
| **总 Token** | **437,684** |
| 模型调用 | **36 次** |

可以看出，**输入约占四分之三**。开销不仅来自生成故事，还来自反复读取市场证据、规划创作和独立审查。

| 阶段 | 调用次数 | 输入 Token | 输出 Token | 合计 Token |
| --- | ---: | ---: | ---: | ---: |
| 证据原子整理 | 1 | 69,514 | 20,797 | 90,311 |
| A/B/C 路线生成 | 3 | 24,801 | 10,202 | 35,003 |
| 候选卡映射（含重试） | 10 | 39,400 | 27,302 | 66,702 |
| 故事创作（含重试） | 10 | 71,457 | 21,998 | 93,455 |
| 故事编辑（含重试） | 10 | 8,968 | 5,230 | 14,198 |
| 市场适配复核 | 1 | 59,437 | 12,769 | 72,206 |
| 原创性复核 | 1 | 59,284 | 6,525 | 65,809 |
| **总计** | **36** | **332,861** | **104,823** | **437,684** |

仅证据整理、市场适配复核和原创性复核就用了 **228,326 Tokens**，超过整批的一半。因此，后续降低消耗的方向不只是缩短故事，还包括压缩重复证据、让不同环节只看需要的材料、控制失败重试和避免无意义的重复审核。这些是可改进方向，**不是已经实测达到的节省比例**。

### 关于费用与适用范围

- 上述数字来自**该批模型响应返回的 Token 统计**，是一次历史 `quality_strict` 策略运行的模型调用用量；包括留存响应中的重试，不代表新版默认 `abc_branch_one` 或其他模型一定消耗相同数量。
- **Token 不等于账单金额**。实际成本取决于计算资源、运行时间和服务商的计费方式；使用云端模型时应按实际输入、输出和缓存价格计算。
- 这些统计只覆盖留存的 **36 次候选流程模型响应**，不包括平台网页抓取、其他独立实验或未保存在这批响应文件中的请求。
- [查看可复核的阶段用量汇总 JSON](../examples/showcase/candidate_token_usage_20260905.json)。只公开调用次数和 Token 汇总，不公开模型请求正文、私有服务地址和原始响应。

### 查看自己的候选运行消耗

项目提供离线用量汇总命令：

```bash
python scripts/candidate_usage.py --run-dir "<候选运行目录>"
```

工具只读取执行目录中保留的 `raw/*.response.json`，按阶段汇总模型响应中的输入、输出 Token 与调用数；不调用模型、不读取账号凭据。没有有效 `usage` 的调用会单独标记为未知，不会当作零成本。统计结果用于诊断，不能直接等同于费用或保证不同模型之间的可比性。
